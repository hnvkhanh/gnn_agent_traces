Per-action guard results with AgentPoison

A graph neural network reads each agent trace as a causal graph and labels every tool call as the user's (approve) or the attacker's (reject). AgentPoison adds backdoored retrieval: a trigger in the question pulls poisoned examples from EHRAgent's memory or a poisoned passage from StrategyQA's knowledge base. Scores are on held-out task families and held-out triggers, with no overlap between training and test (audit below). The guards are near perfect on AgentPoison because its target action never changes, and they fail completely once that action is held out too.

Does the guard catch an unseen backdoor target?

AgentPoison has a single target action per agent (DeleteDB, Finish("I don't know")), shared by every trigger. With held-out triggers the target action is still one the guard saw in training, and every guard recognises it from the action alone: removing memory, observations or the injected text changes nothing (see the ablations). Training on one agent and testing on the other also holds out the target action. Then no guard rejects anything.

Reading these numbers

  • EHRAgent's target action, DeleteDB, is an attacker-only tool, so the tool-lookup baseline does well on that half. StrategyQA's target is Finish("I don't know"), the same tool the benign task ends with.
  • The AgentPoison in-benchmark scores measure recognising a known target action. The held-out-target rows are the ones to quote for an unseen backdoor.
  • The 80 triggers are fixed stand-ins (Verb the adjective noun.). AgentPoison optimises its triggers against a specific retriever and publishes none. Retrieval uses token overlap in place of DPR.
  • When the LLM does not attack by itself, a synthetic attacker step is appended at the end of the trace, so attack traces always end with a reject. The real-only scores in results/REPORT.md leave those steps out.
  • Numbers are means over 3 seeds. With a few hundred traces per benchmark, differences under about 0.05 are within noise.
